# Differentiation: from generated code to dependable outcomes

## The client is not buying code
The client is buying a reduction in repetitive work with a controlled level of operational risk. Code generation is only one step.

## Required controls
1. **Input contracts:** validate file formats, required columns, types, sizes and API payloads before processing.
2. **Safe previews:** show intended changes before writing, moving, deleting or sending records.
3. **Deterministic validation:** reconcile counts, totals, keys and output schemas after execution.
4. **Exception handling:** separate rejected, retriable and manually reviewable records.
5. **Idempotency:** prevent repeat runs from creating duplicate side effects.
6. **Audit trail:** record timestamps, run IDs, outcomes and error categories without logging credentials or sensitive payloads.
7. **Human approval:** require confirmation for destructive or externally visible actions.
8. **Repeatability:** provide CLI instructions, configuration, tests and sample data.
9. **Observability:** expose success/failure counts, duration and retry metrics.
10. **Measured value:** compare a documented manual baseline with a repeatable automated run.

## Honest positioning
AI assistants can generate code and help debug it. Our value is packaging the workflow, testing edge cases, validating results, integrating with existing systems, providing safe operations and supporting the user when real data behaves differently from the demo.
